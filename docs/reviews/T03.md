## F01 — P2 날짜 dtype 고정 조건 미충족

위치는 `src/time_series.py` 70~73행과 반환 스키마 처리 93~98행이다. pandas 3.1.1에서 빈 입력은 `일자` 컬럼을 `datetime64[ns]`로 반환하고 유효한 날짜가 있는 입력과 실제 배포 데이터는 `datetime64[us]`로 반환한다. 따라서 T03의 빈 결과·일반 결과 dtype 동일 조건을 충족하지 못한다.

현재 `test_empty_prepared_history_has_the_same_schema()`는 날짜 컬럼이 없는 일반 입력과 빈 결과를 비교한다. 둘 다 날짜가 전부 결측이라 이 불일치를 검출하지 못한다.

재현은 다음과 같다.

```python
empty = prepare_trend_data(pd.DataFrame(), pd.DataFrame())
numbers = pd.DataFrame({
    '회차': [101], '일자': ['2026-01-03'],
    '당첨번호': [[1, 2, 3, 4, 5, 6]], '보너스번호': [7],
})
populated = prepare_trend_data(numbers, pd.DataFrame())
assert empty.dtypes.to_dict() == populated.dtypes.to_dict()  # 실패
```

수정 방향은 반환 날짜의 단위를 하나로 명시적으로 정규화하고, 유효 날짜를 포함한 일반 입력과 실제 로더 입력을 빈 결과와 비교하는 회귀 사례를 추가하는 것이다. 수정 후 빈 입력·날짜 결측·일반 날짜의 동일 스키마를 확인해야 한다. 이 리뷰 시점의 소스는 검토한 상태이며 해당 수정은 대기 중이다.

## 추가 확인 — 혼합 날짜 형식

`['2026-01-03', '2026.01.17']`을 전달하면 두 번째 날짜가 `NaT`가 된다. 현행 `pd.to_datetime(errors='coerce')`가 첫 번째 날짜 형식을 기준으로 추론하기 때문이다. 현재 실제 로더 입력은 이 문제를 재현하지 않는다. 입력 계약에서 혼합 날짜 문자열도 지원할지 정하고, 지원할 경우 `format='mixed'` 등 명시적인 파싱 정책과 검증 사례를 적용한다. 이 항목은 지원 범위 확인 사항으로 관리한다.
