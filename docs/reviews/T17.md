### F01 — P2 기존 패턴 UI 완화 테스트의 무작위 의존

실패 위치는 `tests/test_pattern_preference_ui.py`의 `test_ui_shows_relaxation_and_invalid_settings()`다. 단일 관측 이력에서 모든 후보가 필터를 탈락할 것으로 가정하고 stage=3을 고정 기대하지만, 실제 유일 관측 번호 `(2, 11, 16, 25, 34, 35)`가 후보에 들어오면 모든 필터를 통과한다. `engine.draw(candidates=[winning])`에서 stage=0과 세 필터의 위반 없음 상태를 직접 재현했다. 관측 여섯 번호의 샘플 가중치 합은 약 0.315789다.

따라서 최초 실패는 정상 후보가 무작위 풀에 포함되며 드러난 기존 테스트의 불안정성이다. 단일 관측 번호와 겹치지 않는 여섯 번호로 후보를 고정하면 모든 쌍이 미관측이므로 stage=3을 보장할 수 있다. 테스트의 render 호출 안에서만 공개 `draw(candidates=...)` 경로에 결정적 후보를 전달하는 수정과 재검증을 요청한다. 운영 RNG나 추출 동작은 변경할 필요가 없다.

T17 자체 진입·피드백·세션 분리 소스에서는 추가 실행 오류를 발견하지 못했다. 수정 커밋을 받아 전체 테스트를 다시 확인한다.


## 기존 패턴 UI 테스트의 무작위 의존성 수정 — v6.2.28

최종 독립 실행에서 기존 완화 UI 테스트가 stage 3 기대와 달리 stage 0으로 실패했다. 유일한 관측 조합 자체는 정상 필터를 통과할 수 있어 무작위 후보 풀에서 그 조합이 생길 때 기존 기대가 성립하지 않았다. 공개 `draw(candidates=...)` 인자를 scoped patch로 사용해 관측 조합과 겹치지 않는 후보를 테스트에서 지정했다. 실제 엔진·UI로 완화 단계와 안내를 검증하고 실행 후 patch를 복원한다. 전체 테스트 184개 통과.
