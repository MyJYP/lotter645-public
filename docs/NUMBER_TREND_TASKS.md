# 번호 차트 작업 분해와 토큰 예산

[핵심 설계](NUMBER_TREND_DESIGN.md)의 출현 흐름·당첨금 배분·보너스 번호를 대상으로 한다. **큰 작업 6개, 세부 태스크 18개, 작업량 37점**으로 나눈다. 18개 중 기능 구현은 15개, 통합 검증·배포는 3개다. 현재 T01~T09 완료, 나머지 9개는 예정이다.

## 작업을 나누는 기준

- 태스크 하나는 검증 가능한 결과 하나를 갖는다. 코드 수정과 그 결과를 확인하는 직접 검증까지 완료 조건에 포함한다.
- 입력·출력 구조나 공통 데이터 규칙을 먼저 정하고, 그 결과를 사용하는 계산과 UI를 순서대로 구현한다.
- 파일 하나를 여러 태스크가 수정할 수 있다. 태스크 경계는 함수 개수나 코드 줄 수보다 데이터 흐름과 완료 조건을 기준으로 삼는다.
- 태스크가 3점을 초과할 것으로 보이면 구현 전에 나누고, 변경한 태스크 수와 합계를 이 문서에 반영한다.
- 점수는 예상 코드량, 예외 처리, 통합 범위를 함께 평가한다. 실제 소요 토큰으로 보정한다.

| 크기 | 점수 | 판단 기준 |
|---|---|---|
| S | 1 | 규칙이 명확한 연결·표시·기존 결과 재사용 |
| M | 2 | 하나의 계산 또는 데이터 변환과 결측·경계 처리 |
| L | 3 | 여러 결과를 결합하는 계산, 상호작용 UI, 여러 경로의 회귀 검증 |

## 토큰 예산 기준

첫 예산은 **1점당 2,000~4,000토큰**을 임시 가정한다. 현재 프로젝트의 실측값은 확보 전이다. 작업량을 예산으로 환산하기 위한 시작 가정이며 첫 묶음 완료 후 교체한다.

| 대상 | 점수 | 가정에 따른 작업 토큰 예산 |
|---|---|---|
| 최초 데이터 준비 | 5 | 10,000~20,000 |
| 전체 작업 | 37 | 74,000~148,000 |

위 범위는 필요한 소스·지시 읽기, 구현, 검증, 결과 정리의 작업량을 가정한 값이다. 긴 대화의 재전송, 추가 컨텍스트 읽기, 도구 출력, 재시도에 따라 총 사용량은 달라진다. 캐시된 입력·일반 입력·출력·추론 토큰의 집계와 가격은 실행 환경의 사용량 표시를 기준으로 확인한다. 표시 항목이 없으면 해당 값은 미측정으로 기록한다.

첫 묶음의 사용량을 확인할 수 있으면 `소모 토큰 ÷ 5점`을 초기 실측 단가로 삼고, 남은 `32점`의 예산을 다시 계산한다. 데이터 작업의 단가를 UI 작업에 적용할 때는 불확실성을 함께 기록하고, UI 묶음 완료 후 한 번 더 보정한다. 작업 묶음 사이의 토큰 집계는 같은 기준으로 비교한다.

토큰을 줄이기 위한 실행 규칙은 다음과 같다.

- 작업 시작 시 이 문서의 해당 행, 설계의 해당 절, 실제 변경할 함수와 직접 호출부를 우선 읽는다.
- 공통 입력 구조를 먼저 완료해 뒤쪽 계산과 화면의 재작업을 줄인다. 기존 HTML 시안과 차트 렌더링 코드를 활용한다.
- 각 태스크에서는 직접 영향을 받는 검증을 실행한다. 통합 단계에서 관련 전체 테스트를 실행하고, 추가 변경이나 실패가 있을 때 필요한 범위를 다시 확인한다.
- 로그는 실패 원인과 결과 요약을 중심으로 읽고, 전체 데이터와 동일 소스의 반복 출력을 줄인다.
- 묶음 종료 시 완료 ID, 변경 파일, 검증 결과, 남은 문제, 다음 ID를 짧게 기록한다. 다음 세션은 이 기록과 필요한 소스에서 이어간다.

작업 기록은 `묶음 / 완료 ID / 변경 파일 / 검증 결과 / 사용 토큰과 집계 기준 / 다음 ID`로 남긴다. 태스크 완료는 해당 행의 완료 조건을 충족했을 때 기록한다.

## T01 실행 기록

사용자의 상세 태스크 1개 실행 요청에 따라 T01을 완료했다. `src/time_series.py`에 `validate_trend_numbers(frame)`를 추가했다. 기존 회차·본번호 검증을 재사용하며, 보너스 범위·본번호 중복을 검사하고 결측을 nullable 정수로 보존한다. 반환값은 과거순이며 입력은 복사한다. T02에서 `prepare_trend_data()`의 입력 검증으로 연결한다.

검증은 신규 검증 사례와 기존 패턴 특징 검증을 합쳐 24개 통과했다. 실제 CSV의 601~1249회 649건도 통과했다. 소스 수정 시 패치 버전 증가 요청을 반영해 로컬 버전은 v6.2.6이다. 다음 작업은 T02다. 토큰 측정은 [T01 사용량 기록](NUMBER_TREND_T01_USAGE.md)에 보관한다.


## T02 실행 기록

`prepare_trend_data(numbers_df, prizes_df)`를 구현해 T01 검증을 실제 데이터 준비 경로에 연결했다. 회차 기준 일대일 결합, 1·2등 금액과 게임 수의 비음수 정수 검증, 필드별 제외 사유를 반환한다. Decimal로 문자열 금액을 읽고 Python 정수를 보관해 결측 회차 결합에서도 큰 정수 정밀도를 보존한다.

관련 테스트 40개 및 실제 CSV 649회차의 결합·정수·제외 사유 확인을 통과했다. 로컬 버전은 v6.2.7, 다음 작업은 T03이다. T01의 MAC23_Lect 리뷰 인계 상태는 [인계 문서](NUMBER_TREND_REVIEW_HANDOFF.md)에 기록했다.


## T03 실행 기록

`prepare_trend_data()`의 반환 컬럼·dtype을 고정하고 컬럼 없는 빈 입력도 처리한다. 날짜 누락·파싱 실패는 `NaT`로 보존하며 입력의 부가 컬럼은 제거한다. `summarize_trend_coverage()`는 최초·마지막 회차, 마지막 회차의 날짜, 관측·누락·결측 보너스 회차 수를 반환한다. 누락 회차는 0으로 채우지 않고 관측 행만 보존한다. 금액 자료에만 있는 회차로 범위를 확장하지 않는다.

신규 경계 테스트를 포함한 `test_number_trends.py`와 `test_pattern_features.py` 49개가 통과했다. 실제 CSV 601~1249회 649건, 누락 회차·결측 보너스 0건, 마지막 추첨일 2026-11-07 및 금액 정수 보존도 확인했다. 로컬 버전은 v6.2.8이다. 전체 3/18개 완료, 다음은 T04다. 커밋·푸시·배포는 수행하지 않았다. 토큰 사용량은 미측정이다.

## T04 실행 기록

`build_appearance(history, kind="main"/"bonus")`를 구현했다. 최초~마지막 회차의 연속 인덱스와 45개 번호 출현 행렬을 만들고 5·10·20·60·120회 횟수·출현률을 전체 이력에서 계산한다. 누락 회차·결측 보너스는 결측 행으로 보존하고 이를 포함한 창은 자료 부족으로 남긴다. 본번호 통계는 결측 보너스에 영향을 받지 않는다. 입력 검증·과거순 정렬을 재사용하고 빈 입력에도 고정 스키마를 반환한다. 교차와 표시 범위 처리는 T05 범위다.

관련 테스트 69개 통과. 각 기간의 N-1/N 경계, 40%·15% 검산, 45개 번호, 누락 이후 회복, 보너스 결측, 본번호·보너스 분리, 입력 불변·역순·비연속 인덱스·미래 자료 추가 불변성을 확인했다. 실제 CSV 649회차에서 모드별 29,205행을 생성했고, 각 모드에서 5개 창 × 3개 기준 회차 × 45개 번호의 675건을 별도 직접 집계로 검산했다. 출현률 범위 0~100과 유효 창 개수도 확인했다.

로컬 v6.2.9, 전체 4/18개 완료, 다음 T05. 커밋·푸시·배포 미수행. 토큰 사용량 미측정.


T04 리뷰는 [태스크별 결과](reviews/T04.md)에 기록했다. 관련 테스트 69개와 독립 표본 4,500건·실제 마지막 회차 450건 검산을 통과해 T04 수정 필요 지적은 없다. T03 F01은 이후 v6.2.10에서 수정·재검증을 완료했다.

## T05 실행 기록 — v6.2.11

`build_appearance()`에 nullable string `cross`를 추가했다. 번호별 직전 회차의 정수 출현 횟수 차이로 `up/down/none`을 판정하고, 두 창 중 하나라도 부족하면 결측으로 반환한다. `recent_rounds=None`은 전체, 양의 정수는 마지막 회차 기준 최근 N회다. 범위 선택은 모든 계산 후 수행한다.

## T06 실행 기록 — v6.2.12

`prepare_prize_rounds(history, basis="total", rank=1)`를 구현했다. 준비된 이력에서 회차별 게임당 금액·당첨게임 수·사용 금액·제외 사유·산출 근거를 반환한다. `basis`는 total/per_game, `rank`는 1/2이며 T11에서 2등 집계에 재사용한다.

## T07 실행 기록 — v6.2.13
