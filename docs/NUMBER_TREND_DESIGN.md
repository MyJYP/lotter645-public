# 번호 차트 핵심 구현 설계

[기획서](NUMBER_TREND_PLAN.md)를 구현하기 위한 설계다. 대상 기능은 출현 흐름, 당첨금 배분, 보너스 번호이며 현재 공개 소스 v6.2.5를 기준으로 작성했다.

구현 순서·완료 조건·토큰 예산은 [세부 작업 목록](NUMBER_TREND_TASKS.md)에 정리했다.

## 파일과 호출 구조

| 파일 | 구현 내용 |
|---|---|
| `src/time_series.py` | 아래 데이터 준비·출현률·당첨금·보너스 계산 함수를 추가 |
| `src/number_trend_ui.py` | `render_number_trends(loader)`에서 세 화면과 Plotly 차트를 렌더링 |
| `src/web_app.py` | `data_exploration_page()`의 네 번째 탭에서 렌더링 함수 호출 |
| `tests/test_number_trends.py` | 계산·결측·금액 합계 검증 |
| `tests/test_number_trend_ui.py` | 실제 데이터 탐색 진입과 위젯 변경 검증 |

```text
data_exploration_page(loader)
  └─ 재미로 보는 번호 차트
      └─ render_number_trends(loader)
          ├─ prepare_trend_data(loader.numbers_df, loader.df)
          ├─ 출현 흐름 → build_appearance(history, kind="main")
          ├─ 당첨금 배분 → build_prize_allocation(history, start, end, basis)
          └─ 보너스 번호 → build_appearance(history, kind="bonus")
                         + summarize_bonus(history, start, end)
```

## 입력 데이터

`prepare_trend_data(numbers_df, prizes_df) -> DataFrame`은 `회차`로 두 입력을 일대일 결합한다. `normalize_draw_history()`의 본번호·회차 검증을 재사용하고 계산용 복사본을 과거순으로 정렬한다.

| 입력 컬럼 | 의미·검증 |
|---|---|
| `회차`, `일자` | 회차는 양의 고유 정수. 날짜가 없으면 화면에 날짜 미상 표시 |
| `당첨번호` | 1~45의 서로 다른 정수 6개 |
| `보너스번호` | 1~45 정수이며 같은 회차의 본번호와 중복 금지. 결측은 유지 |
| `1등 당첨액`, `2등 당첨액` | 공시된 게임당 세전 금액. 유효한 비음수 정수를 원 단위로 사용 |
| `1등 당첨자수`, `2등 당첨자수` | 당첨게임 수. 유효한 비음수 정수 |

중복 회차·잘못된 번호는 입력 오류로 반환한다. 금액·게임 수의 결측, 음수, 비정수는 해당 금액 계산의 제외 대상으로 표시한다. 번호 통계에 필요한 유효 행은 활용한다. 빈 입력은 정해진 컬럼을 가진 빈 결과로 반환한다.

### T03 반환 스키마와 자료 범위

`prepare_trend_data()`의 반환 컬럼 순서는 `회차`, `일자`, `당첨번호`, `보너스번호`, 1등 당첨액·당첨자수, 2등 당첨액·당첨자수, 같은 순서의 필드별 제외 사유로 고정한다. 부가 입력 컬럼은 반환하지 않는다. 날짜는 datetime으로 변환하고 없거나 해석할 수 없으면 `NaT`로 보존한다. 컬럼 없는 빈 DataFrame도 허용하며 빈 결과에도 동일한 컬럼과 dtype을 제공한다. 데이터가 있는 입력의 필수 컬럼 누락은 계속 오류다.

`summarize_trend_coverage(prepared_history)`는 준비된 전체 관측 이력에서 `start_round`, `end_round`, `last_draw_date`, `observed_rounds`, `missing_rounds`, `missing_bonus_rounds`를 반환한다. 누락 회차 수는 최초~마지막 회차의 범위 길이에서 관측 행 수를 뺀 값이며, 결측 보너스는 별도로 센다. 빈 이력의 시작·끝은 `None`, 마지막 날짜는 `NaT`, 건수는 0이다. 마지막 회차의 날짜가 없으면 이전 날짜로 대체하지 않는다. 금액 자료에만 존재하는 회차는 관측 범위를 늘리지 않는다.

준비 결과에는 관측 행만 둔다. 누락 회차를 미출현 0으로 채우지 않으며 T04에서 전체 정수 회차 인덱스를 만들고 결측으로 재색인한다. 범위 요약은 DataFrame 메타데이터 대신 별도 순수 함수로 제공한다.

## 출현 흐름 계산

`build_appearance(history, kind="main", recent_rounds=None) -> DataFrame`은 `(회차, 번호)`당 한 행을 반환한다. 번호는 1~45 전체를 포함한다. 결과 컬럼은 `appeared`, `count_5/10/20/60/120`, `ma_5/10/20/60/120`, `cross`다.

1. 시작~마지막 회차의 정수 인덱스를 만들고 번호별 출현 행렬을 구성한다. `main`은 본번호 포함 여부, `bonus`는 보너스 일치 여부를 1·0으로 기록한다. 미관측 회차와 결측 보너스는 해당 행렬에서 결측값으로 둔다.
2. 기간 `N ∈ {5,10,20,60,120}`마다 `rolling(N, min_periods=N).sum()`을 계산한다. `ma_N = count_N × 100 / N`이다.
3. `d = 4 × count_5 − count_20`으로 교차를 판단한다. 직전 `d ≤ 0`, 현재 `d > 0`이면 `up`, 직전 `d ≥ 0`, 현재 `d < 0`이면 `down`, 그 외 유효한 경우 `none`이다. 현재·직전 값 중 하나라도 결측이면 교차도 결측이다.
4. 전체 이력에서 계산한 뒤 화면 표시 범위를 자른다. 최근 N회 범위는 `max(최초 회차, 마지막 회차 − N + 1)`부터 마지막 회차까지다.

T04에서 `build_appearance(history, kind="main")`의 출현 행렬과 5·10·20·60·120회 횟수·출현률을 구현했다. 반환은 회차·번호 오름차순이며 최초~마지막 회차의 각 회차에 번호 1~45 전체를 포함한다. 빈 입력도 같은 컬럼·dtype을 반환한다. `appeared`는 관측 0/1 또는 결측, 횟수·출현률은 결측을 표현할 수 있는 float다. **교차 컬럼 `cross`와 표시 범위 처리는 T05에서 추가한다.** T04는 전체 이력을 반환한다.

화면은 출현률 0~100%, 결측 구간 선 끊김을 적용한다. 이론 기준선은 본번호 `6/45 × 100`, 보너스 `1/45 × 100`이다. `none`은 “교차 없음”, 결측은 “자료 부족”으로 표시한다.

`recent_rounds=None`은 전체 이력이며, 양의 정수는 마지막 보유 회차 기준 최근 N회다. 입력 검증 후 전체 교차를 먼저 계산하고 마지막에 조회 범위를 잘라 첫 표시 회차의 교차를 유지한다. `cross`는 nullable string이며 `up/down/none` 또는 자료 부족의 결측값이다.

## 당첨금 배분 계산

T06의 `prepare_prize_rounds(history, basis="total", rank=1)`는 회차별 `회차/per_game/winning_games/amount/exclusion_reason/amount_source`를 반환한다. rank는 1·2를 지원하고, 금액은 Python 정수 또는 결측이다. 유효한 0게임은 두 기준 모두 amount=0으로 처리한다. 결측·이상값 제외 사유와 산출 근거를 함께 반환한다.

`build_prize_allocation(history, start=None, end=None, basis="total") -> dict`에서 `basis`는 `total` 또는 `per_game`이다. 기간을 먼저 선택하고 아래 금액을 집계한다.

```text
P(t) = 1등 게임당 금액 × 당첨게임 수     [total]
P(t) = 1등 게임당 금액                   [per_game]
A(t,n) = P(t) × 본번호 출현 여부

회차 배분액 = A(t,n) / 6
누적 배분액 = 기간 내 A(t,n)의 누적 합 / 6
출현 회당 평균 = 기간 내 A(t,n)의 합 / (6 × 금액 집계에 포함된 출현 횟수)
```

`A`와 누적 합은 Python 정수로 보관한다. 화면 표시·Plotly 좌표 변환 단계에서 나누고 반올림한다. 평균의 분모가 0이면 “해당 기록 없음”으로 표시한다.

반환 구조는 다음과 같다.

| 항목 | 내용 |
|---|---|
| `series` | 회차·번호별 `allocation_numerator`, `cumulative_numerator` |
| `summary` | 번호별 누계 분자, 전체 본번호 출현 횟수, 금액 집계에 포함된 출현 횟수 |
| `rounds` | 회차별 게임당 금액·게임 수·사용 금액·제외 사유 |
| `coverage` | 요청 범위, 유효 회차 수, 누락 회차 수, 금액 제외 회차 수, 집계 금액 합계 |

유효한 당첨게임 수가 0이면 두 모드 모두 해당 회차의 배분액을 0으로 둔다. 게임 수가 양수이고 게임당 금액이 없으면 제외한다. 제외 회차의 배분액은 결측으로 표시하며 누계는 유효 금액만 더한다. 화면에 제외 건수를 함께 표시한다. 누적선은 선택한 기간 시작 직전의 누계 0을 기준으로 한다.

현재 CSV의 총액은 게임당 금액과 게임 수를 곱해 산출한다. 화면에는 “총액 산출 · 게임당 금액 × 당첨게임 수”와 “공시 당첨금 기준·세전”을 표시한다. 회차별 공식 총액 컬럼을 도입하면 유효한 공식 총액을 우선하도록 입력 규칙을 확장한다.

## 보너스 번호 집계

`summarize_bonus(history, start, end) -> dict`는 번호별 `summary`, 보너스 등장 회차별 `events`, 자료 범위 `coverage`를 반환한다. 이동평균은 `build_appearance(kind="bonus")`를 재사용한다.

| 결과 | 계산 규칙 |
|---|---|
| 출현 횟수·출현률 | 선택 기간의 보너스 출현 수 ÷ 유효한 보너스 관측 회차 수 |
| 마지막 출현·경과 회차 | 선택 기간에서 마지막 등장 회차와 종료 회차의 차이. 미등장은 “선택 기간 내 기록 없음”. 중간 결측은 표시 |
| 출현 간격 | 보너스 등장 회차의 양의 차이. 사이에 결측 보너스가 있는 간격은 평균에서 제외 |
| 본번호 비교 | 같은 기간의 본번호 출현 횟수와 유효 본번호 관측 회차 수를 함께 표시 |
| 다음 회차 본번호 | `t`의 보너스가 `t+1` 본번호에 포함된 건수 / 관측 가능한 사건 수. 두 회차 모두 선택 기간 안에 있고 실제 `t+1` 자료가 있어야 함 |
| 2등 금액 | 해당 번호가 보너스였던 회차의 게임당 금액·게임 수·총액 합계. 금액 결측과 당첨게임 0건은 1등 집계와 같은 규칙 적용 |

다음 회차가 없으면 관측 미완료로 센다. 2등 총액은 해당 보너스 번호로 묶은 회차 금액이며 화면 명칭은 “보너스 등장 회차의 2등 총액 합계”로 표시한다.

## 화면 연결

`render_number_trends(loader)`는 `출현 흐름 / 당첨금 배분 / 보너스 번호` 선택에 따라 해당 계산과 화면을 실행한다. 기본 진입은 출현 흐름이다.

| 화면 | 입력과 기본값 | 출력 |
|---|---|---|
| 출현 흐름 | 번호 1, 최근 100회, 5·20·60·120회선 선택. 10회선 추가 가능 | 기간별 출현률, 차트, 교차 설명, 45개 번호 표 |
| 당첨금 배분 | 총액 기준, 전체 보유 회차, 비교 번호 최대 6개 | 누계 순위·누적선·평균·회차 상세·집계 제외 수 |
| 보너스 번호 | 번호 1, 최근 100회, 출현 흐름과 같은 선 선택 | 보너스 차트·순위·본번호 비교·다음 회차 기록·2등 금액 |

출현 흐름·보너스의 기간 선택은 50·100·200회·전체, 금액은 60·120회·전체로 제공한다. 표의 번호 선택은 세션의 번호 위젯 값에 반영한다. 조회 조건은 `number_trend_` 접두사의 위젯 키로 관리한다. 금액의 기본 비교 번호는 `[1]`로 정한다.

계산 함수는 입력 DataFrame으로 결과를 반환하는 순수 함수로 작성한다. 캐시가 필요하면 UI 모듈의 `st.cache_data`에 전체 입력과 계산 인수를 전달한다. 오류는 해당 섹션에 표시한다. 상단에 실제 보유 회차·마지막 추첨일, 하단에 기획서의 동일 확률 안내·계산 규칙·공식 출처 링크를 표시한다.

## 필수 검증

| 검증 | 통과 기준 |
|---|---|
| 이동평균·교차 | 5회 중 2회는 40%. 119회에서 120회선 결측, 120회부터 값 생성. 상향·하향·동률·자료 부족을 구분 |
| 시계열 정합성 | 역순·비연속 인덱스에서도 동일 결과. 미래 자료 추가와 표시 기간 변경이 과거 값을 바꾸지 않음. 누락을 포함한 창은 결측 |
| 금액 정확성 | 120억 원·본번호 1~6은 각 20억 원. 전체 번호 누계 합이 사용한 금액 합과 일치. 게임 수 2일 때 총액·게임당 모드의 값은 2배 차이 |
| 금액 경계 | 미등장·유효 0원·결측 금액·0게임을 구분. 평균은 금액 집계에 포함된 출현 수로 계산. 6으로 나누어떨어지지 않는 금액도 합계 보존 |
| 보너스 | 출현 수 합계가 유효 보너스 회차 수와 일치. 결측·마지막 회차·누락된 다음 회차를 전이 실패로 세지 않음 |
| UI 경로 | 실제 데이터 탐색에서 세 화면 진입, 번호·기간·기준 변경, 모바일 차트와 출처 링크 확인 |

T01~T03의 번호 검증·금액 결합·빈 입력·자료 범위 처리를 구현했다. `prepare_trend_data()`가 번호 검증을 호출하며 `summarize_trend_coverage()`가 자료 범위를 반환한다. 나머지 계산과 UI는 작업 목록에 따라 진행한다.


## T07·T08 반환 계약

`start/end=None`은 보유 범위의 최초·마지막 회차를 사용한다. 명시적으로 지정한 기간은 해당 범위에서 누계를 시작하며, 미관측 회차도 결측 행으로 포함한다. 경계는 양의 정수이며 시작은 끝 이하이어야 한다. 빈 이력에서 양쪽 경계를 생략하면 빈 시계열·빈 상세와 번호 45개의 0원 누계 요약을 반환한다.

- `series`는 회차·번호·`allocation_numerator`·`cumulative_numerator`다. 금액 분자는 Python 정수이며 회차 배분액은 분자를 6으로 나눈 값이다. 제외·미관측 회차의 배분액은 결측, 누계는 유효 금액의 누적값이다.
- `summary`는 번호·`cumulative_numerator`·`appearance_count`·`valid_appearance_count`·`average_allocation`이다. 평균은 `Fraction(누계 분자, 6 × 유효 출현 수)`이고 유효 출현이 없으면 결측이다. 화면에서 최종 단위 변환과 반올림을 수행한다.
- `rounds`는 회차·게임당 금액·게임 수·사용 금액·최종 제외 사유·산출 근거·날짜·본번호다. 미관측 회차는 “관측 회차 없음”으로 표시한다.
- `coverage`는 `start_round/end_round/basis/observed_rounds/missing_rounds/valid_prize_rounds/excluded_prize_rounds/total_amount`다. 금액 제외 수는 관측 회차에서만 세고 미관측 수와 분리한다. 모든 요약 누계 분자 합은 `6 × total_amount`와 일치해야 한다.

T06은 입력에 저장된 필드별 제외 사유를 최종 제외 사유로 보존한다. 저장된 사유가 없는 입력은 직접 파싱 결과를 사용한다. 0게임이면 금액 오류 사유가 있어도 해당 회차의 사용 금액은 0으로 처리한다.
